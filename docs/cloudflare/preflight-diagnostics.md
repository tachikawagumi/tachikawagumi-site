# 読み取り専用preflightの診断成果物

`Cloudflare Pages - frozen cleanup` の `mode=preflight` に限る改善です。
手動実行・main限定・読み取りトークン・二度のAPI取得を維持します。
この変更のPR作成時には、実際のpreflight/API接続を実行していません。

## 保存内容と失敗時の扱い

- `cleanup-diagnostics.json`: 固定219件・候補177件・保護42件に対する各APIスナップショットの新規、欠落、属性変更、保護判定の変化、不明項目。
- `cleanup-diagnostics.md`: 同じ情報の日本語レポート。新規デプロイのID、日時、ブランチ、環境、URL、alias、実行時保護理由を確認できます。
- `cleanup-preflight.json`: 従来の成功時のみの成果物。診断ファイルで置き換えません。

API取得前に未完了の診断ファイルを作成します。取得したメタデータから診断を保存した後、従来の照合を実施します。失敗した段階を記録して例外を再送出するため、ジョブは失敗のままです。2回目の取得・照合で失敗した場合も、既に観測した情報を保持します。

新規ID、属性不一致、保護状態の変化、不明な値で停止します。読み取り専用preflightでは欠落も人による確認が必要な差分として停止します。共有の `reconcile()` と削除側の欠落・承認判定は変更しません。

upload-artifactの `if: always()` を維持し、JSONに加えて診断Markdownもアップロードします。既存と同じ7日間保持です。チェックアウトや事前の安全検査で止まり診断処理に到達しなかった場合、API診断が存在することは保証しません。アップロード自体の失敗や強制終了も保証対象外です。

## 機密情報と承認の扱い

APIの生レスポンス、例外メッセージ、画像、GPS座標、環境変数一覧は保存しません。許可したメタデータ項目のみ抽出し、型・長さ・形式を検証します。URLは対象Pagesプロジェクトと公式ドメインのHTTPSのみで、認証情報・クエリ・フラグメントは認めません。既知のトークン・Account IDが値に含まれる場合も値を伏せ、固定された理由だけを記録して安全停止します。判定できない項目は `null` / `unknown` とします。

新規IDは常に `new-unapproved`・`fixed_deletion_candidate=false`・`approved_for_deletion=false` です。診断は削除承認になりません。manifest・承認JSONは読み取りのみで、自動更新しません。削除ジョブ、削除専用ワークフロー、承認条件、現行本番保護ID、Access、ドメイン、サイト本体に変更はありません。
